# 正文与程序元数据

## 本轮确认的原文优先流程

DeepSeek候选是定位线索，正文证据来自按账号、会话、消息及实际文本指纹回读的原始聊天。普通闲聊可按细粒度价值判断略过；本人明确提出存档、记入笔记、补充现稿或整理感想的材料须单独核对原意图与实质内容，不因为screen为skip或引用/容量校验失败就自动排除。缺附件/录音另列缺口，不能视为已经理解或没有价值。

生成前同时读取原始相关问答和当前主稿，保留后续纠正、认可与完整细节。新bundle在原始会话总文字不超过既有60k界限时带入完整会话；超过时保持原有界证据与邻接，不截断强塞，记录未包含消息数，另按相关主题补读。候选标题/摘要不提供额外事实；旧AI文字可因本人明确存档意图保存为参考，但不能转写成本人原创或实际经历。

新任务冻结`source-first-v1`规则与实际请求。旧manifest、profile、任务输入、模型原回复和判定不回写；新规则不触发重发或预算重置。当前有限整理可由Agent回原文处理模型漏项，另留编辑身份和来源，不冒充DeepSeek自动通过。保存仅进入私人库，不选择网站发布版本。

新任务采用 `markdown-content-v1`：模型写普通 Markdown 正文，程序维护来源身份、标题、代码记录和哈希。旧任务保留原请求及格式约定，不因升级改写历史。

用户明确选择候选后，程序冻结上下文并校验来源与消息身份。初稿以一级标题开始，代码直接用普通围栏；模型无需填写来源编号、代码清单或文件信息。程序从实际正文提取标题和代码块，对照原文记录匹配情况。来源标记 `input-context-only` 只说明输入过哪些上下文，不证明每句话有对应引证，也不表示内容经过事实核查。

初稿先保存，再执行独立语义复核。复核依据原文检查忠实性、观点归属、背景和独立可读性，返回 `markdown`、`verdict`、`reason` 三个字段。用户自述、引用的旧助手文字和事后补充必须分清；缺失的日期、结果和证明不能补编成事实。

每目标最多初稿、独立复核两个阶段，每阶段输出上限为 8,000 token。正文完整但复核超时、预算不足、内容待确认或代码来源需要核对时，保留可读稿进入待复核。明确阅读确认后才允许入库，原复核状态继续保留。空回复、只有标题、输出截断或供应商错误不能视作完成。

调用先占账，原始回复先保存，实际用量与未知费用预留分别记录。已有回复优先离线解析；已有调用却没有回复时先对账，不自动重发。工作区、请求、写入日志和哈希用于恢复，不能通过删除账本、换目录或改任务身份重新收费。重启使用 `--no-resume` 可阻止自动恢复保存的队列。

生成、下载、入库和网站发表各自独立。入库使用 `obsidian-workflow` 的来源身份与写入守卫；重复入库复用已有笔记，不覆盖用户之后的修改。待复核确认不修改原模型判定，入库也不表示稿件获准公开。

隔离测试覆盖模拟初稿、复核异常、预算阻断、代码提示、崩溃恢复、费用去重、用户编辑保护及旧格式兼容。测试验证程序行为，不保证未来模型的语义准确率；真实使用仍需检查正文与来源缺口。
